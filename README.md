# Virtual AIoT Lab — ด่านที่ 1 ฮาร์ดแวร์และเซนเซอร์

ห้องปฏิบัติการวิศวกรรม AIoT และสมองกลฝังตัวเสมือนจริงแบบ 3 มิติบนเว็บ สำหรับนักเรียน ม.ปลาย ใช้ในงานแนะแนว / Open House ของ **สาขาวิชาวิศวกรรมระบบอัจฉริยะและนวัตกรรมดิจิทัล (SI)** คณะวิศวกรรมศาสตร์ มหาวิทยาลัยกรุงเทพ

นักเรียนเลือกอุปกรณ์จากชั้นวาง ต่อวงจรบนเบรดบอร์ด 3D ติดตั้งเซนเซอร์ อ่านค่าจากสภาพแวดล้อมจำลอง ตั้งกฎ IF–THEN ให้ระบบทำงานเอง ทำแบบทดสอบ และรับใบประกาศ ใช้เวลาประมาณ 15–20 นาที

> ⚠️ ค่าทั้งหมดมาจาก **แบบจำลองอย่างง่ายเพื่อการเรียนรู้** (DC + first-order lag) ไม่ใช่โปรแกรมจำลองวงจรเต็มรูปแบบ (SPICE) — แอปแจ้งข้อความนี้ในหน้าแรก แผงวงจร และทฤษฎีภารกิจ

---

## 1. ติดตั้งและรัน

ต้องมี Node.js 20 ขึ้นไป

```bash
npm install
npm run dev        # เปิด http://localhost:5173
npm test           # unit test (Vitest)
npm run build      # สร้างเว็บ static ในโฟลเดอร์ dist/
npm run preview    # ทดลองเปิดไฟล์ที่ build แล้ว
```

ทดลองบนมือถือในวง WiFi เดียวกัน: `npm run dev -- --host` แล้วเปิด `http://<IP เครื่อง>:5173` บนมือถือ

## 2. Deploy (เว็บ static)

**Vercel:** New Project → เลือก repo → Framework: Vite → Build command `npm run build` → Output `dist`
**Netlify:** Build command `npm run build` → Publish directory `dist`

แอปใช้ hash route (`#staff`) จึงไม่ต้องตั้งค่า rewrite ใด ๆ ใส่ environment variable ในหน้าตั้งค่าโปรเจกต์ของ Vercel/Netlify ได้ (ดูข้อ 3) แล้ว build ใหม่

หลัง deploy เปิด **โหมดนำเสนอ** (ปุ่มที่หน้าแรกหรือเมนู ⚙️) เพื่อแสดง QR Code ของ URL ให้นักเรียนสแกน

## 3. การตั้งค่า (environment variables — ไม่บังคับ)

คัดลอก `.env.example` เป็น `.env.local`

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `VITE_STAFF_PIN` | PIN หน้าผู้สอน/สตาฟ (`#staff` หรือปุ่ม "ผู้สอน/สตาฟ") | `2468` |
| `VITE_SUPABASE_URL` | URL ของโปรเจกต์ Supabase | — |
| `VITE_SUPABASE_ANON_KEY` | anon (public) key ของ Supabase | — |

ถ้าไม่ตั้งค่า Supabase แอปทำงานได้ครบทุกฟังก์ชันด้วย localStorage และหน้าผู้สอนจะแจ้งชัดว่าเป็น "ข้อมูลเฉพาะเครื่อง"

> PIN ถูกตรวจในเบราว์เซอร์และฝังอยู่ในไฟล์ JavaScript ที่ build แล้ว จึงป้องกันได้แค่ระดับเบาสำหรับงานกิจกรรม ไม่ใช่ระบบยืนยันตัวตน

### ตั้งค่า Supabase (ไม่บังคับ)

สร้างตารางใน SQL Editor:

```sql
create table public.lab_results (
  id text primary key,
  nickname text not null default '',
  school text not null default '',
  started_at timestamptz not null,
  finished_at timestamptz not null,
  duration_s integer not null,
  quiz_score integer,
  quiz_total integer not null default 5,
  missions_passed integer[] not null default '{}',
  challenge text,
  auto_score integer,
  hints_used integer not null default 0,
  guided boolean not null default false,
  created_at timestamptz not null default now()
);
-- ถ้าสร้างตารางไว้ก่อนมีโหมดพาทำ ให้เพิ่มคอลัมน์ด้วย:
-- alter table public.lab_results add column if not exists guided boolean not null default false;

alter table public.lab_results enable row level security;

-- ผู้เล่นส่งผล (insert/upsert) ได้
create policy "anon insert" on public.lab_results for insert to anon with check (true);
create policy "anon update" on public.lab_results for update to anon using (true) with check (true);
-- หน้าผู้สอนอ่านผลรวม
create policy "anon read" on public.lab_results for select to anon using (true);
```

ข้อควรรู้ด้านข้อมูลส่วนบุคคล: policy `anon read` ทำให้ใครก็ตามที่มี anon key (ซึ่งอยู่ในไฟล์ JS) อ่านชื่อเล่น/โรงเรียนได้ แอปจึงเก็บเพียงชื่อเล่นและชื่อโรงเรียน (ไม่บังคับกรอก) ถ้าต้องการปิดการอ่านจากภายนอก ให้ลบ policy `anon read` แล้วดูสถิติจากหน้า Supabase Dashboard หรือส่งออก CSV จาก Dashboard แทน

## 5. แบบจำลองทางวิศวกรรม (สรุป)

| เรื่อง | ค่าที่ใช้ |
|---|---|
| ลอจิกบอร์ด | 3.3V, ADC 12 บิต (0–4095) อ้างอิง 3.3V แบบเชิงเส้น (มีหมายเหตุว่า ADC ESP32 จริงไม่เชิงเส้นและอิ่มตัวใกล้ ~3.1V) |
| ขาพิเศษ | GPIO34–39 input-only, ADC2 ใช้ไม่ได้ขณะเปิด WiFi (เตือน), กระแส GPIO แนะนำ ≤ ~12 mA เกิน 20 mA เตือน |
| LED | V_f แดง ≈ 2.0V, เขียว/น้ำเงิน ≈ 3.0V, I = (V − V_f)/R → 220Ω กับ LED แดง ≈ 5.9 mA |
| ตัวต้านทาน | 220Ω แดง-แดง-น้ำตาล-ทอง, 1kΩ น้ำตาล-ดำ-แดง-ทอง, 10kΩ น้ำตาล-ดำ-ส้ม-ทอง |
| DHT22-like | อ่านทุก 2 s, ละเอียด 0.1, offset ±0.3 °C/±1.5 %RH + noise, เวลาตอบสนอง τ ≈ 6 s, ไม่มีไฟ/สายหลุด → NaN |
| LDR | R = 20kΩ·(lux/10)^−0.7 → วงจรแบ่งแรงดัน → ADC (รองรับ LDR อยู่ฝั่ง 3V3 หรือฝั่ง GND) |
| ความชื้นในดิน | แห้ง ≈ ADC 3050, เปียก ≈ 1300, Calibrate ค่าแห้ง/เปียกได้ |
| PIR | ต้องการ 5V, warm-up 10 s (หมายเหตุ: ของจริง 30–60 s), hold time ปรับ 1–10 s |
| สภาพแวดล้อม | ห้อง 28 °C, ฮีตเตอร์ +15 °C, พัดลม −5 °C, τ = 20 s, ช่วง 20–45 °C; แสง 20–1300 lux; ดินแห้งลงตามเวลา (เร่งเวลา) |
| วงจรผิด | ลัดวงจร → ตัดไฟทันที, LED ไม่มี R → กระแสเกิน/เสียหายจำลอง, ขาลอย → ค่าสุ่มกระโดด, ขาไม่ใช่ ADC → อ่านไม่ได้, พัดลมต่อตรง GPIO → ไม่หมุน + เตือน |

## 7. ผลการทดสอบ

**Unit test (Vitest): 62 ข้อ ผ่านทั้งหมด** — `npm test`

- โหมดพาทำ: "นักเรียนจำลอง" ทำตามทุกขั้นของภารกิจ 2, 3, 4 และ 5 (ทั้งห้องเรียนและกระถาง) แล้วได้วงจรที่ทำงานจริง และทดสอบอัตโนมัติผ่าน 4/4; รูอื่นในคอลัมน์เดียวกันผ่าน; LED กลับขั้วมีคำเตือน; วงจรที่ต่อเองแบบอื่นแต่ถูกจะถูกข้าม; ลัดวงจรมีคำเตือน

- Netlist และการตรวจวงจร: ลัดวงจร 3V3–GND / 3V3–5V, USB, LED ถูก (5.91 mA @220Ω), 1kΩ (1.3 mA), 10kΩ (หรี่เกิน), LED เขียว (1.36 mA), ไม่มี R, กลับขั้ว, ขา input-only, ขาด GND, ขาลัด, DHT ขาด VCC/GND/DATA, DATA บน input-only, DHT ใช้ 5V (เตือน), LDR ทั้งสองทิศ, LDR บนขาไม่ใช่ ADC, ไม่มีตัวต้านทานคู่, ดินบนขาไม่ใช่ ADC/ADC2, PIR ใช้ 3.3V, ต่อขั้วไฟกลับ, พัดลมผ่านโมดูล / ต่อตรง GPIO / ไม่มีสัญญาณ IN, บัซเซอร์กลับขั้ว
- สภาพแวดล้อม: เปลี่ยนค่อยเป็นค่อยไป ลู่เข้าเป้าหมาย clamp ช่วงค่า ความชื้นลดเมื่ออุ่นขึ้น การรดน้ำและแห้งลง
- เซนเซอร์: DHT อ่านทุก 2 s ละเอียด 0.1 ความคลาดเคลื่อน เวลาตอบสนอง NaN, LDR power law สูตรแบ่งแรงดัน ADC 12 บิต ค่าลอย, Calibrate ดิน, PIR warm-up/hold
- เฟิร์มแวร์: LED ติดเฉพาะเมื่อ GPIO HIGH + มีไฟ, ไม่ยอมจ่ายไฟเมื่อลัดวงจร, LED ไม่มี R เสียหาย, Serial, กฎปิดวงจรควบคุม (ร้อน → พัดลม → เย็นลง)
- กฎ/โค้ด: ELSE, ข้อมูลไม่ถูกต้อง, โค้ดใช้เลขขาจริง
- ทดสอบอัตโนมัติ: เฉลยห้องเรียน 4/4, พัดลมต่อตรง GPIO ไม่ผ่าน, เฉลยกระถาง 4/4, กฎไม่ครบได้ 0/4
- แบบทดสอบ + CSV escape/BOM

**End-to-end ในเบราว์เซอร์ (dev server, เดสก์ท็อป 1024×768 และมือถือ 375×812):**

- ภารกิจ 0: หมุนกล้อง เลือกชิ้นส่วน ต่อสายจริงด้วยการแตะ → ผ่าน
- ภารกิจ 1: การ์ดอุปกรณ์ 6 ชิ้น + mini quiz → ผ่าน
- ภารกิจ 2: กรณีผิด — LED ไม่มีตัวต้านทาน (เตือนอันตราย + ไฮไลต์ + LED เสียหายจำลอง), LED กลับขั้ว (ไม่ติด); กรณีถูก — 5.91 mA, LED ติด, กระพริบ → ผ่าน
- ภารกิจ 3: ฮีตเตอร์ 100% ค่าอุณหภูมิขึ้น 28.0 → 30.6 °C ภายในไม่กี่วินาที (อ่านทุก 2 s) → ผ่าน
- ภารกิจ 4: ไฟเต็ม ADC ≈ 3837, ปิดไฟ+ม่าน ADC ≈ 1839, ตอบคำถามผิดถูกปฏิเสธ ตอบถูกผ่าน → ผ่าน
- ภารกิจ 5 (ห้องเรียน): ไม่มีกฎได้ 1/4, ตั้งกฎแล้ว 4/4; ระบบเปิดพัดลมและไฟเองเมื่อร้อนและมืด → ผ่าน
- ภารกิจสุดท้าย: แบบทดสอบ → หน้าสรุป → ใบประกาศ PNG/PDF สร้างได้
- หน้าผู้สอน: PIN ผิดถูกปฏิเสธ, PIN ถูกแสดงสถิติ + ข้อความ "ข้อมูลเฉพาะเครื่อง"
- โหมดนำเสนอ: ตัวอักษรใหญ่ขึ้น + QR Code
- โหมดพาทำ (ภารกิจ 2): ปุ่มบนการ์ด เสียบ USB → ลูกศรชี้ขา GND และราง − → แตะวางตัวต้านทานตรงเงาสีเขียวได้ตำแหน่งถูก → ลอง LED กลับขั้วแล้วมีคำเตือน → ทำครบจนผ่านภารกิจ; บนมือถือการ์ดย้ายไปอยู่ในแผงด้านล่างไม่บังฉาก
- Console ไม่มี error; production build ไม่มี dev hook หลงเหลือ

**สิ่งที่พบและแก้ระหว่างทดสอบ:** กล้องสำเร็จรูปตัดภาพบนจอแคบ (ปรับระยะตามสัดส่วนจอ), LED ที่ติดมองเห็นยากเมื่อปิด bloom (เพิ่ม halo), เวลาจำลองช้ากว่าความเร็วที่เลือกเมื่อเฟรมเรตต่ำ (ปรับ loop), แถบเครื่องมือและผู้ช่วยบังฉากบนมือถือ (ย่อเป็นไอคอน)

## 8. ข้อเสนอสำหรับด่านถัดไป

**ด่านที่ 2 ฝังปัญญาประดิษฐ์ (Edge AI)**
- ใช้ Data Log จากด่าน 1 เป็นชุดข้อมูล ให้นักเรียนติดป้ายกำกับ (เช่น "ร้อนอึดอัด/สบาย") แล้วฝึกโมเดลเล็ก ๆ (decision tree / kNN) ในเบราว์เซอร์ เทียบกับกฎ IF–THEN ที่ตั้งเอง
- จำลองข้อจำกัดของ MCU: หน่วยความจำ เวลาประมวลผลต่อการอนุมาน และ quantization
- เพิ่ม hysteresis และ moving average เพื่อสอนเรื่องการกรอง noise ก่อนส่งเข้าโมเดล
- ต่อยอดโมดูล `engine/firmware.ts` ให้รับ "โมเดล" แทน `evaluateRules`

**ด่านที่ 3 ระบบควบคุมและคลาวด์ (Control & Cloud Integration)**
- จำลอง WiFi + MQTT/HTTP (latency, ข้อมูลหาย) และแดชบอร์ดบนคลาวด์ ใช้ Supabase Realtime เป็น broker ตัวอย่าง
- ควบคุมอุปกรณ์จากมือถือนักเรียนคนอื่นแบบ multi-user ในห้องเดียวกัน
- สอนเรื่องความปลอดภัย IoT (คีย์ การยืนยันตัวตน) และเหตุผลที่ ADC2 ใช้ไม่ได้เมื่อเปิด WiFi ซึ่งปูไว้แล้วในด่าน 1
- แยก `services/results.ts` เป็นชั้น backend จริง และเปลี่ยน PIN หน้าผู้สอนเป็นการยืนยันตัวตนฝั่งเซิร์ฟเวอร์

**ปรับปรุงด่าน 1 ต่อ:** ทดสอบบน iOS Safari/Android ระดับกลางจริงและวัด FPS, ทดสอบการลากวางด้วยนิ้ว, ทดสอบ Supabase จริง, เพิ่ม e2e test อัตโนมัติ (Playwright), เพิ่มป้ายบนชั้นวางให้อ่านง่ายขึ้นบนจอเล็ก, รองรับ screen reader ในฉาก 3D มากขึ้น
